Browser automations are built in code using three layers: Page (AI-enhanced Playwright), Agent (multi-step AI goals), and Browser (cloud Chromium instance). This page lists every operation available on a Page or through an Agent. For the full SDK documentation with all parameter options, see the [SDK Reference](/sdk-reference/browser-automation/page#page-act).

If you're building automations visually instead, see [blocks reference](/reference/blocks) for the equivalent operations in the Cloud UI agent editor.

|--------|---------|---------|

| [`upload_file`](#upload_file) | Upload a file to a file input (Python only) | `str` |

## Page actions

### act

Perform any action described in natural language.

<CodeGroup>
```python Python
await page.act("Click the login button")
await page.act("Scroll down to the pricing section")
```

```typescript TypeScript
await page.act("Click the login button")
await page.act("Scroll down to the pricing section")
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | `str` | Yes | What action to perform |
| `skip_refresh` | `bool` | No | Skip page refresh before acting. Not forwarded by the SDK, so it has no effect here |
| `use_economy_tree` | `bool` | No | Use a smaller DOM tree for faster processing. Not forwarded by the SDK, so it has no effect here |

**Returns:** `None`

**SDK reference:** [act](/sdk-reference/browser-automation/page#page-act)

### extract

Pull structured data from the visible page.

<CodeGroup>
```python Python
data = await page.extract(
    "Extract all product names and prices",
    schema={
        "type": "array",
        "items": {
            "type": "object",
            "properties": {
                "name": {"type": "string"},
                "price": {"type": "number"},
            },
        },
    },
)
```

```typescript TypeScript
const data = await page.extract({
    prompt: "Extract all product names and prices",
    schema: {
        type: "array",
        items: {
            type: "object",
            properties: {
                name: { type: "string" },
                price: { type: "number" },
            },
        },
    },
})
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | `str` | Yes | What to extract |
| `schema` | `dict \| list \| str` | No | JSON Schema for typed output |
| `error_code_mapping` | `dict` | No | Map custom error codes |

**Returns:** `dict`, `list`, `str`, or `None`

**SDK reference:** [extract](/sdk-reference/browser-automation/page#page-extract)

### prompt

Send a prompt to the LLM and get its answer. The model does not see the page: it gets only your prompt text. To read data from the page, use [`extract`](#extract).

<CodeGroup>
```python Python
result = await page.prompt(
    "Classify this support message as billing, bug or other: 'I was charged twice this month'",
    schema={"type": "object", "properties": {"category": {"type": "string"}}}
)
```

```typescript TypeScript
const result = await page.prompt(
    "Classify this support message as billing, bug or other: 'I was charged twice this month'",
    { type: "object", properties: { category: { type: "string" } } }
)
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | `str` | Yes | Prompt to send |
| `schema` | `dict` | No | JSON Schema for structured response |
| `model` | `dict \| str` | No | Override LLM model config, or a model name as a string |

**Returns:** `dict`, `list`, `str`, or `None`. Without a `schema`, returns a `dict` of the form `{"llm_response": "..."}` (TypeScript: `{ llmResponse: "..." }`). With a `schema`, returns data shaped to your schema.

**SDK reference:** [prompt](/sdk-reference/browser-automation/page#page-prompt)

### click

Click an element using a selector, AI prompt, or both.

<CodeGroup>
```python Python
await page.click("#submit-button")                                       # selector
await page.click(prompt="Click the 'Submit' button")                     # AI
await page.click("#submit-button", prompt="Click the 'Submit' button")   # both
```

```typescript TypeScript
await page.click("#submit-button")                                       // selector
await page.click({ prompt: "Click the 'Submit' button" })                // AI
await page.click("#submit-button", { prompt: "Click the 'Submit' button" })  // both
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS selector |
| `prompt` | `str` | No | AI prompt (fallback or primary) |
| `ai` | `str` | No | AI mode: `"fallback"` (default) tries the selector first, then AI; `"proactive"` uses AI first; `None` uses the selector only. Python only |
| `mode` | `str` | No | `"direct"` performs a plain Playwright click, with no AI fallback. Python only |

**Returns:** `str | None` (resolved selector)

**SDK reference:** [click](/sdk-reference/browser-automation/page#page-click)

### type

Enter text into an input. `type` behaves the same as `fill`: with a selector, the value is set in one step rather than typed key by key. For fields that react to individual key presses (search autocomplete, OTP inputs), use [`fill_autocomplete`](#fill_autocomplete) or `press_sequentially` on a Playwright locator. Python only.

```python
# Input via selector
await page.type("#search", value="wireless headphones")

# AI-powered type
await page.type(prompt="Type 'hello' into the search box")

# Selector with AI fallback
await page.type("#search", value="query text", prompt="Type into the search field")
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS or XPath selector for the input field |
| `value` | `str` | No | Text to enter |
| `prompt` | `str` | No | Natural-language description of the target field |
| `ai` | `str` | No | AI mode: `"fallback"` (default) tries the selector first, then AI; `"proactive"` uses AI first; `None` uses the selector only |
| `totp_identifier` | `str` | No | Identifier of the 2FA code to enter, when `value` is a TOTP placeholder. See [Two-factor authentication](/credentials#two-factor-authentication). |
| `totp_url` | `str` | No | Endpoint Skyvern calls to fetch the 2FA code, when `value` is a TOTP placeholder |

**Returns:** `str` (the value entered)

**SDK reference:** [type](/sdk-reference/browser-automation/page#page-type)

### upload_file

Upload a file to a file input. Pass a selector for direct Playwright behavior, a prompt for AI-powered file input detection, or both. Python only.

```python
# Direct selector
await page.upload_file("#file-input", files="https://example.com/resume.pdf")

# AI-powered file input detection (no selector needed)
await page.upload_file(prompt="Upload the resume to the file input")

# Selector and prompt: the selector is tried first, then AI performs the upload,
# using the selector only if it worked
await page.upload_file(
    "#file-input",
    files="https://example.com/resume.pdf",
    prompt="Upload the resume to the file input",
)
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS or XPath selector for the file input |
| `files` | `str` | No | URL of the file to upload. One file per call |
| `prompt` | `str` | No | Natural-language description of the file input to target. With the default `ai`, a prompt means AI performs the upload |
| `ai` | `str` | No | AI mode: `"fallback"` (default) tries the selector first, then AI; `"proactive"` uses AI first when a `prompt` is given; `None` uses the selector only |

**Returns:** `str` (the URL of the file uploaded)

**SDK reference:** [upload_file](/sdk-reference/browser-automation/page#page-upload_file)

### locator

Locate an element using a CSS/XPath selector, an AI prompt, or both. When called with a `prompt`, returns an `AILocator`, a lazy Playwright `Locator` that resolves the element via AI on first use. Python only.

```python
# AI-powered: pass a natural-language prompt
locator = page.locator(prompt="the submit button")
await locator.click()

# Full Playwright chaining works
text = await page.locator(prompt="the error message").text_content()

# Standard Playwright selector (no AI, identical to vanilla Playwright)
locator = page.locator("#submit-btn")
await locator.click()

# Selector with AI fallback: try the selector first, use AI if it fails
locator = page.locator("#submit-btn", prompt="the submit button")
await locator.click()
```

<Note>
When called with only a `selector` (no `prompt`), `page.locator(selector)` behaves exactly like the standard Playwright `page.locator(selector)`. No AI is involved.
</Note>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS or XPath selector passed to Playwright's built-in `locator()` |
| `prompt` | `str` | No | Natural-language description of the element. When provided, returns an `AILocator` that resolves via AI |
| `ai` | `str` | No | AI mode: `"fallback"` (default) tries the selector first, then AI |
| `**kwargs` |  | No | Additional keyword arguments forwarded to Playwright's `locator()` |

**Returns:** `Locator` (standard Playwright `Locator` when only a selector is given, or `AILocator` when a prompt is provided)

#### AILocator methods

When `prompt` is provided, the returned `AILocator` supports all standard Playwright `Locator` methods:

- **Actions:** `click()`, `fill()`, `type()`, `select_option()`, `check()`, `uncheck()`, `clear()`, `hover()`, `focus()`, `press()`
- **Queries:** `text_content()`, `inner_text()`, `inner_html()`, `get_attribute()`, `input_value()`, `count()`
- **State:** `is_visible()`, `is_hidden()`, `is_enabled()`, `is_disabled()`, `is_editable()`, `is_checked()`
- **Chaining:** `first()`, `last()`, `nth()`, `filter()`, `locator()`, `get_by_text()`, `get_by_role()`, `get_by_label()`, `get_by_placeholder()`
- **Utilities:** `wait_for()`, `screenshot()`

**SDK reference:** [locator](/sdk-reference/browser-automation/page#page-locator)

## Agent methods

All agent methods return either a [`TaskRunResponse`](/sdk-reference/runs#run_task) (for `agent.run_task`) or a [`WorkflowRunResponse`](/sdk-reference/agents#run_workflow) (for `agent.login`, `agent.download_files`, `agent.run_workflow`). Follow the links for the full field list.

### agent.login

Authenticate with stored credentials. Handles multi-page login flows, CAPTCHAs, and 2FA.

<CodeGroup>
```python Python
await page.agent.login(
    credential_type="skyvern",
    credential_id="cred_123"
)
```

```typescript TypeScript
await page.agent.login("skyvern", {
    credentialId: "cred_123"
})
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `credential_type` | `CredentialType` | No | `skyvern` (default), `bitwarden`, `1password`, or `azure_vault` |
| `credential_id` | `str` | No | Credential ID (required for `skyvern` type) |
| `bitwarden_collection_id`, `bitwarden_item_id` | `str` | No | Bitwarden item to use (for `bitwarden` type) |
| `onepassword_vault_id`, `onepassword_item_id` | `str` | No | 1Password item to use (for `1password` type) |
| `azure_vault_name`, `azure_vault_username_key`, `azure_vault_password_key`, `azure_vault_totp_secret_key` | `str` | No | Azure Key Vault secrets to use (for `azure_vault` type) |
| `url` | `str` | No | Login page URL. Defaults to the current page URL |
| `prompt` | `str` | No | Additional login instructions |
| `webhook_url` | `str` | No | Callback URL for the run result. See [Webhooks](/developers/production#webhooks). |
| `totp_identifier` | `str` | No | Identifier for push-based TOTP. See [Two-factor authentication](/credentials#two-factor-authentication). |
| `totp_url` | `str` | No | Endpoint Skyvern calls to pull TOTP codes |
| `extra_http_headers` | `dict[str, str]` | No | Additional HTTP headers to include in requests |
| `timeout` | `float` | No | Max wait time in seconds (default: 1800) |

**Returns:** [`WorkflowRunResponse`](/sdk-reference/agents#run_workflow)

**SDK reference:** [agent.login](/sdk-reference/browser-automation/agent#page-agent-login)

### agent.run_task

Run a multi-step AI task on the current page.

<CodeGroup>
```python Python
result = await page.agent.run_task(
    "Go to the billing page and download the latest invoice",
    data_extraction_schema={
        "type": "object",
        "properties": {
            "invoice_number": {"type": "string"},
            "amount": {"type": "string"},
        },
    },
)
print(result.output)
```

```typescript TypeScript
const result = await page.agent.runTask(
    "Go to the billing page and download the latest invoice",
    {
        dataExtractionSchema: {
            type: "object",
            properties: {
                invoice_number: { type: "string" },
                amount: { type: "string" },
            },
        },
    },
)
console.log(result.output)
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | `str` | Yes | Multi-step goal description |
| `data_extraction_schema` | `dict \| str` | No | JSON Schema for structured output. See [Extract Structured Data](/developers/browser-automation#extract-structured-data). |
| `max_steps` | `int` | No | Cap AI steps. The run ends with status `failed` ("Reached the maximum steps") if hit. Controls cost; each step is one AI decision + action cycle. |
| `engine` | `RunEngine` | No | AI engine. Defaults to `skyvern-1.0`, which the SDK always sends. Other options: `skyvern-2.0`, `skyvern-3.0`, `openai-cua`, `anthropic-cua`, `ui-tars`. See [Engines](/concepts#engines). |
| `model` | `dict` / `Record<string, unknown>` | No | Override LLM model configuration |
| `url` | `str` / `string` | No | URL to navigate to (defaults to current page URL) |
| `webhook_url` | `str` / `string` | No | Callback URL. Skyvern POSTs the full run result on completion or failure. See [Webhooks](/developers/production#webhooks). |
| `totp_identifier` | `str` / `string` | No | Identifier for push-based TOTP. See [Two-factor authentication](/credentials#two-factor-authentication). |
| `totp_url` | `str` / `string` | No | Endpoint Skyvern calls to pull TOTP codes. See [Two-factor authentication](/credentials#two-factor-authentication). |
| `title` | `str` / `string` | No | Display name for this run |
| `error_code_mapping` | `dict` / `Record<string, string>` | No | Map custom error codes to conditions. Keys are your error codes, values describe when to trigger them. If matched, the run's `errors` list contains an entry with `error_code` set to your code. |
| `user_agent` | `str` / `string` | No | Custom User-Agent header for the browser |
| `timeout` | `float` | No | Max wait in seconds (default: 1800) |

**Returns:** [`TaskRunResponse`](/sdk-reference/runs#run_task)

**SDK reference:** [agent.run_task](/sdk-reference/browser-automation/agent#page-agent-run_task)

### agent.download_files

Navigate and download files from the current page.

<CodeGroup>
```python Python
result = await page.agent.download_files(
    "Download the latest invoice PDF",
    download_suffix="invoice",
    download_timeout=30,
)
```

```typescript TypeScript
const result = await page.agent.downloadFiles(
    "Download the latest invoice PDF",
    {
        downloadSuffix: "invoice",
        downloadTimeout: 30,
    },
)
```
</CodeGroup>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | `str` | Yes | What to download |
| `url` | `str` | No | Page to start from. Defaults to the current page URL |
| `download_suffix` | `str` | No | Filename for the saved file. | `download_timeout` | `float` | No | Soft hint (seconds) for how long to wait for a download. The overall `timeout` is what actually fails the run. |
| `max_steps_per_run` | `int` | No | Cap AI steps |
| `webhook_url` | `str` | No | Callback URL for the run result. See [Webhooks](/developers/production#webhooks). |
| `totp_identifier` | `str` | No | Identifier for push-based TOTP. See [Two-factor authentication](/credentials#two-factor-authentication). |
| `totp_url` | `str` | No | Endpoint Skyvern calls to pull TOTP codes |
| `extra_http_headers` | `dict[str, str]` | No | Additional HTTP headers to include in requests |
| `timeout` | `float` | No | Max wait in seconds (default: 1800) |

**Returns:** [`WorkflowRunResponse`](/sdk-reference/agents#run_workflow)

### extract_form_fields

Extract all form fields with metadata from the current page. Use the output to drive `fill_from_mapping` or `validate_mapping`.

```python
fields = await page.extract_form_fields()
# Returns one dict per field. A mapping refers to a field by its position in this list:
# [{"label": "First Name", "selector": "...", "tag": "input", "type": "text", "name": "first_name", "required": True, ...}, ...]
```

**Returns:** `list[dict[str, Any]]`. Each dict has `label`, `selector`, `tag`, `type`, `name` (the HTML `name` attribute), `required` and `placeholder`. Two more keys depend on the field:

- `formatHint` is a string, or `None` when the field has no hint. It is missing from toggles (`type` of `toggle`), radio and checkbox groups, and ARIA checkboxes.
- `options` is a list. It is present only on dropdowns (`type` of `select`) and on radio and checkbox groups (`type` of `radio_group` or `checkbox_group`).

Read both with `field.get(...)`.

**SDK reference:** [extract_form_fields](/sdk-reference/browser-automation/forms#page-extract_form_fields)

### fill_autocomplete

Fill an input that has autocomplete/typeahead behavior. Types the value, waits for suggestions, then clicks the matching option.

```python
# Direct selector
await page.fill_autocomplete(
    selector="#city",
    value="San Francisco",
    option_selector=".autocomplete-option",

# AI-powered

```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS selector for the input field |
| `value` | `str` | No | The text value to type into the field |
| `prompt` | `str` | No | Natural-language description of the field and value |
| `ai` | `str` | No | AI mode: `"fallback"` (default) tries the selector first, then AI; `"proactive"` uses AI first; `None` uses the selector only |
| `option_selector` | `str` | No | CSS selector for the autocomplete dropdown options |
| `wait_seconds` | `float` | No | Seconds to wait for the dropdown to appear. Default `1.5` |

## iframe management (Python only)

### frame_switch

Switch the working context to an iframe. Exactly one of `selector`, `name`, or `index` must be provided.

```python
# By CSS selector
await page.frame_switch(selector="#payment-iframe")

# By frame name
await page.frame_switch(name="checkout")

# By index into page.frames (0 is the main frame, so the first iframe is usually 1)
await page.frame_switch(index=1)
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `selector` | `str` | No | CSS selector for the iframe element |
| `name` | `str` | No | The `name` attribute of the iframe |
| `index` | `int` | No | Index into `page.frames`. `0` is the main frame. |

<Note>
Exactly one of `selector`, `name`, or `index` must be provided.
</Note>

**Returns:** `dict[str, Any]` (frame metadata for the switched-to iframe)

**SDK reference:** [frame_switch](/sdk-reference/browser-automation/frames#page-frame_switch)
