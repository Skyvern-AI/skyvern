## Workflow Copilot, Rebuilt

The refreshed Copilot chat is now **the default everywhere**, in both the workflow editor and Workflow Studio, and it builds with more honesty and less friction:

- **See what happened, not a plan**: build progress is a **flat activity log** of what Copilot looked at, wrote, and ran, with **code diffs for write steps** and narrator lines that explain steps in place
- **Fix one block and rerun**: Copilot can repair one block and rerun it in a single step, and when the browser is still on the edited block's page it re-runs only that block instead of replaying the login. When a code block fails, Copilot gets the recorded browser error, plus the screenshot and any blocking overlay when they were captured
- **Truthful review**: the Accept card shows exactly which blocks are added, changed, or unchanged, Accept and Reject show up **without a reload**, and a new **Test end-to-end** action runs the whole draft in a fresh browser
- **Fewer questions**: pick a connected Google account inline, choose credentials from a **searchable picker**, hand Copilot a saved login by name, and let it **solve captchas** and read **sign-in codes from a connected inbox** instead of stopping to ask

Copilot also learned the human-approval block, knows today's date, keeps the page facts it gathered across long sessions, and stops cleanly when you press the new stop button.

## Skyvern 3.0 Engine (Beta)

Meet the next agent engine. **Skyvern 3.0** drives the browser through a persistent tool loop, and only actions count against your step budget, never perception turns. It is in beta, and you can opt in today:

- **Pin a block to it**: pick **Skyvern 3.0** (marked Beta) in the engine selector on task, navigation, login, action, and extraction blocks, or pass `engine="skyvern-3.0"` on a task run
- **On-demand vision**: when the page's text digest has gaps, the agent takes a **marked-up screenshot** and acts on the numbered marks
- **Logins and challenges built in**: it solves captchas (including hCaptcha), resolves **TOTP and emailed one-time codes**, and follows **emailed magic links** without the link ever reaching the model
- **Form-savvy**: custom comboboxes, click-to-open selects, typeaheads, and shadow-DOM controls commit in one action, it checks that file uploads and toggles took effect instead of assuming, and it waits for the page to settle before calling a block complete

Run replay and typed action history are supported on the new engine.

## Drive Your Own Chrome from MCP

Your real, logged-in browser is now a target. The new **Skyvern Agent** Chrome extension (on the Chrome Web Store) lets Skyvern MCP drive **your own Chrome**, existing sessions, cookies, and profiles included, with `BROWSER_TYPE=extension-connect`. You share only the tabs you choose, pairing takes **one approval** and persists per workstation, and **several coding agents can share one Chrome** at the same time.

The MCP surface grew up too:

- **Tool scopes**: choose `--scope all|operate|build|browser` at install, or pick a scope on the hosted URL, plus an opt-in **`lean`** scope of browser-only tools
- **New tools** in the `lean` and `all` scopes: `skyvern_page` reads a large page with cursor pagination, `skyvern_extract_structured` returns **schema-validated** results, and `skyvern_finish` declares a task's final outcome
- **Hosted MCP**: add Skyvern as a custom connector from **Claude.ai and Claude Desktop**, renew access silently with refresh tokens, and connect to the organization you picked at sign-in

## Credentials: 1Password, Passkeys & More

Logins keep getting easier to wire up and harder to break:

- **1Password in the Login block**: the credential dropdown now lists your 1Password items and binds one directly, a five-step guide walks you through the service account token, and items that keep one-time codes in a plain field can name a **custom TOTP field**
- **Passkey 2FA for every cloud organization**, plus **Outlook** as a source for email two-factor codes
- **Password-less and at-will credentials**: store a credential with a username but no password, and leave a workflow credential's default blank so it **runs unauthenticated unless you pass one at run time**
- **Per-credential controls**: run workflows **sequentially per credential** (scheduled runs included), and Save & Reuse Session keeps **one browser profile per rotating credential**

Under the hood, magic-link and OTP values are stored exactly as received, code blocks and cached scripts can complete an emailed sign-in with a new `magic_link` verb, Bitwarden credential fetches are faster and more reliable, and OTP logins use their full 15-minute polling budget.

## Files, Email & Storage, Your Way

Bring your own infrastructure:

- **S3-compatible storage**: point the File Upload and File Download blocks at your own S3-compatible storage with a new `endpoint_url` field (public HTTPS endpoints by default; self-hosted deployments can allow internal hosts)
- **Custom SMTP**: the Send Email block can send from **your own mail server** under Advanced Settings
- **File retention you control**: set `retention_days` when you upload a file with `POST /v1/upload_file`, delete any upload with `DELETE /v1/files/{id}`, or attach uploads to a run with `file_ids` and let Skyvern delete them when the run ends
- **Google, done right**: File Download uses your connected Drive account for **private Drive files**, the Drive folder ID is optional (blank saves to My Drive root), Google Sheets appends land in the **column you asked for**, and Sheets, Drive, Docs, and Gmail blocks resolve a connection **by name or email**

The File Parser inside a loop can skip files it cannot parse, it follows Drive links behind confirm pages, and a slow parse of a huge document fails only its own block instead of the whole run.

## Browser Sessions & Live View

Sessions that behave like a real desk:

- **Reuse one browser across runs**: the new `reuse_browser_session` workflow setting (with a per-run override) carries logged-in state and tabs from run to run
- **Live view, wider**: externally hosted browsers (US cloud) and session-backed runs now stream a live view, the full page height is reachable in take-control, and the view tells you when its stream stops instead of freezing
- **Friendlier API**: over-limit timeouts are **capped at 240 minutes** and reported in a `warning` field instead of rejected, and a closed session explains its status and what to do next

Recordings from external providers are retained after teardown, and a renewal never shortens a session.

## Code Blocks That Explain Themselves

Code blocks got a real error contract and more honesty when things go wrong:

- **Typed business errors**: declare an `error_code_mapping` on a code block and `raise ErrorCode("out_of_stock", "why")` so run status and webhooks say **which condition failed**
- **Real failure facts**: a failed block reports the failing line, a plain-language next step, and the raised exception when redaction allows, and user-code and browser failures link to the **block screenshot** when one was captured
- **Outputs that show up**: run detail displays persisted code-block output instead of a disabled Outputs panel
- **Sandbox parity**: downloads, `page.url`, `Locator.or_`/`and_`, Python `class` statements, `page.frames`, and the timeouts you wrote all work in the sandboxed runner, and advisory **security-scan warnings** appear when you save code in Copilot or lint through MCP

## Analytics & Run History, Sharper

Better questions, better answers:

- **Group by workflow tag** on the analytics dashboard, alongside the existing run-metadata grouping, for per-tag run and credit chargeback
- **Actions at a glance**: an **Actions** tile with action counts and failure rate joins the dashboard and the workflow health panel, and the run chart switches to a **Failures view** with agents ranked by failures first
- **Status that sticks**: choosing a run status scopes every chart, tile, table, and CSV export, carries into drill-downs, and accepts several statuses at once, and the failure rate now excludes runs you cancelled
- **Run history**: search and status filters persist in the URL, and `GET /runs` accepts a new `failure_category` filter for workflow runs

## Quick List — August

**New features**

- **Child runs in the workflow runs list** — `GET /v1/workflows/{workflow_id}/runs` and the MCP workflow run list accept `include_child_runs`
- **Send Email via API, SDK, and MCP** — `send_email` blocks no longer need platform SMTP parameters declared
- **Bulk agent export** — exporting several agents gives you a ZIP with one file per agent
- **Workflow schema view** — open a workflow's schema/YAML from the header menu in the classic workflow editor
- **Self-hosted stuck-run reaper** — deployments without a cron worker can enable an in-process reaper
- **Cloudflare challenge solving for self-hosted** — self-hosted deployments now get it from the bundled solver extension

**Improvements**

- Workflow Inputs are shown in a card where the flow starts, with the input count in the header
- Studio panes have clearer borders and simpler timeline controls, and the Run Timeline shows elapsed time, blocks, actions, and credits
- Paste a full workflow export into the editor's YAML pane
- New code blocks generated by browser recording, Browser Task steps, and PDF/SOP imports open in the new code block editor
- Delete confirmations use one consistent dialog across the app
- Run detail pages no longer freeze on multi-megabyte output values
- A workflow run with no blocks fails immediately with a specific reason, and an undefined for-loop parameter returns a clear 422
- Ordinary text inputs are filled atomically, and toggles and checkboxes respect their intended state
- Dropdown and custom-select fills verify the value actually committed instead of reporting a false success
- Runs recover from CDN access-denied interstitials and can click data-grid row checkboxes
- Prompts that overflow because of a huge page trim the element tree instead of failing the step
- Proxied stealth browser launches start about 30 seconds faster, and timezone and locale default to the proxy's region unless you set them
- Job-application fills on a major applicant-tracking platform stop fabricating values, commit dates and pickers correctly, recognize submit confirmation, and terminate fast on already-applied postings
- Revoked or rotated API keys stop working within 60 seconds
- The CLI refuses to send an API key to the cloud default unless `SKYVERN_BASE_URL` is set explicitly
- Concurrent SDK `run_action` calls are capped per organization with a 429 instead of degrading everyone
- The API answers 503 with `Retry-After` when the database connection drops, so SDK clients retry
- MCP tools return a structured `SESSION_EXPIRED` result, and large MCP responses are compacted while keeping identifiers and errors
- The standalone MCP server binds to localhost by default (`--host 0.0.0.0` to expose it)
- Connecting a Google integration asks only for that integration's scopes

- Fixed Bitwarden logins without a two-factor secret failing to list or fill
- Fixed downloads lost on adopted, vendor-hosted, and reused browser sessions, in-page PDF blobs, and after a download closed the working page
- Fixed a downloaded file being materialized twice and uploaded as duplicates
- Fixed an aborted browser download being reported as a success with zero files
- Fixed webhook deliveries leaving from a different IP than the documented relay
- Fixed SDK and MCP actions against cloud browser sessions returning HTTP 500
- Fixed live view flickering to black, showing a black screen on session-backed runs, and frames stopping after a reconnect
- Fixed Delete and Backspace not working in the hosted browser live view
- Fixed browser session recordings not being saved after long sessions
- Fixed runs stuck in `queued` after a sequential gate deadline, and runs retrying forever when the workflow body raised
- Fixed saving a workflow with many cached scripts hanging for minutes
- Fixed selecting a block marking the workflow as unsaved, and the Inputs card opening Workflow Settings
- Fixed "Execute on any outcome" blocks being flagged as disconnected or swallowed by a conditional branch
- Fixed run and task view tabs blanking the content area, and shared Studio run links opening the wrong run
- Fixed the Add Credential modal not opening from the Credentials page
- Fixed the analytics dashboard counting cancelled runs as failures, and enterprise plans seeing always-zero credit tiles
