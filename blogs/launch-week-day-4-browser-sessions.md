One of the most common requests we’ve heard:

**“Can Skyvern pick up where it left off?”**

Until now, every run started fresh—like opening a brand new browser window each time. Clean, but sometimes too clean.



<h2 id="why-browser-sessions">Why Browser Sessions?</h2>



Skyvern **Browser Sessions** prop up a browser and let you persist the real-time state of the browser

This unlocks a whole new category of workflows where context matters:

-   <strong>Deploy code straight into the browser —</strong> combine AI navigations and trusty ‘ol code by CDPing into our browser sessions before / after the AI tasks are done
-   <strong>Continuous tasks with no lag —</strong> connect the browser across multiple workflows so you can use Skyvern for real-time executions

* * *



<h2 id="how-it-works">How it works</h2>



1.  <strong>Create a browser session</strong> via API or SDK
2.  <strong>Run tasks inside that session</strong> — they’ll share state, cookies, and progress
3.  <strong>Resume at any time</strong> — reconnect to the session and keep going from where you stopped

📘 [See the docs →](https://docs.skyvern.com/api-reference/api-reference/browser-sessions/create-browser-session)

* * *

🔥 Real-time persistence. Continuous agents. Smarter workflows. We’re hoping Browser Sessions give you flexibility to run, rerun, deploy code, and stay logged in without starting over.
