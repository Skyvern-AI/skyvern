Agents are built from blocks. Each block performs one specific operation: navigating a page, extracting data, making an API call, or branching logic. This page covers every block type available in the Cloud UI [Studio editor](/cloud/studio), grouped by category.

If you're writing automations in code instead, the equivalent operations are Page and Agent methods. See the [actions reference](/reference/actions) for the code-first counterparts to these blocks.

## Common fields

These fields appear on most blocks:

| Field | Description |
|-------|-------------|
| **Label** | Display name on the canvas. Also determines how downstream blocks reference this block's output (`{{ label_output }}`). |
| **Continue on Failure** | Allow the agent to continue if this block fails |
| **On block failure** | Only inside loops, where it replaces **Continue on Failure**. Choose **Stop the loop**, **Continue to next block in this iteration** or **Skip to next iteration**. |
| **Model** | Override the default LLM model for this block (Advanced Settings on most blocks) |

Browser-based blocks (Browser Task, Browser Action, Extraction, Login, File Download) add some of these fields:

| Field | Shown on | Description |
|-------|----------|-------------|
| **URL** | All except Extraction | Starting URL. Leave blank to continue from the previous block's page. |
| **Engine** | All five | AI engine for this block. On Skyvern Cloud, **Default** runs on Skyvern 3.0 in agents created since October 1, 2026. The selector labels Skyvern 3.0 **Recommended** and Skyvern 1.0 and 2.0 **Legacy**. See [Choose an engine per block](/cloud/studio#choose-an-engine-per-block). |
| **Max Steps Override** | All except Browser Action | Cap the number of AI reasoning steps |
| **Disable Cache** | All five | Skip cached script execution |
| **2FA Identifier** | All except Extraction | ID that links 2FA codes to this block. When empty, the block uses the selected credential's identifier, if it has one. |
| **2FA Verification URL** | All except Extraction | Endpoint this block polls when it needs a 2FA code |
| **Error Messages** | All except Extraction | Map error conditions to custom error codes (JSON) |

<Note>
Set **2FA Verification URL** on the block that may encounter 2FA. A `totp_url` set on the run does not fill empty block fields.
</Note>

The block shows the same fields for every engine except Skyvern 2.0. Skyvern 2.0 is offered only on blocks that already use it; those blocks stay editable with a reduced field set.

## Data and Extraction

### Web Search

Search Google or Exa over an API. Add `site:example.com` to the query to search within a site. This block does not open a browser or read linked pages.

Google supports site restrictions. With a single `site:domain` or `site:domain/path` filter, the block removes results outside the filter. It repeats the search up to twice when Google returns only results outside that filter. It does not filter queries with quotation marks, parentheses, `|`, `OR`, or multiple `site:` filters. Exa supports one positive `site:domain` filter. Unsupported Exa expressions fail instead of expanding the search.

| Field               | Type     | Description                                                              |
| ------------------- | -------- | ------------------------------------------------------------------------ |
| **Search Query**    | text     | Required query. Supports input and output parameter references.          |
| **Search Provider** | selector | Automatic (default), Google, or Exa. Google uses SerpAPI.                |
| **Maximum Results** | integer  | Between 1 and 100; default 10. The provider may return fewer results.    |
| **Prompt**          | text     | Optional instructions to summarize, rank, extract, or transform results. |
| **Model**           | selector | Model for Prompt, Data Schema, and error detection.                      |
| **Data Schema**     | JSON     | Optional output shape. Works with or without a Prompt.                   |
| **Error Messages**  | mapping  | Error codes and descriptions that the model checks against the outcome.  |

Automatic starts with Google. It tries Exa only if Google fails before returning results and the server has an Exa key. Empty results do not trigger fallback. Selecting Google or Exa uses only that provider.

A Prompt receives the normalized results, including an empty list. Without a Data Schema, its answer is text. A Data Schema alone asks the model to return the results in that shape. The answer is stored in `prompt_output`. Invalid schemas are rejected when you save. Schemas with parameter references are checked after those references are filled in. A response that fails validation retries once before the block fails.

Leave Prompt and Data Schema blank to skip result processing. Error Messages still make an LLM call when configured on the block or workflow. Block entries override workflow entries with the same code. The model checks results, processed answers, and block failures against those descriptions, including failures before the search starts.

A successful search completes when no error code matches, including when it returns zero results. A matching code terminates a successful search. If the search or Prompt fails or times out, a matching code attaches to that failure without changing its status or system failure reason. If error detection fails, the block keeps the search outcome without a code.

The old `no_results_error_code` and `no_match_error_code` fields are deprecated. Saved values are read as Error Messages. They describe empty results and results that do not satisfy the Prompt. An explicit Error Messages entry with the same code takes precedence.

The output always includes:

- `query`: the rendered query, or the configured query if rendering fails.
- `provider`: `google` or `exa`.
- `results`: objects with `title`, `link`, `snippet`, `display_link`, and one-based `position`.
- `total_count`: the number of returned results.
- `prompt_output`: null, text, or the JSON value defined by Data Schema.
- `raw_response.pages`: provider responses, with credentials removed.

With Exa, a result's `snippet` is empty when Exa has no cached copy of the page or when the request for page highlights fails.

For example, use `{{ web_search_1_output.results }}` in a downstream block. A later page failure keeps validated partial results and completes the search. A Prompt failure keeps those results but fails the block.

Failed and terminated outputs also include `status`, `failure_reason`, and `errors`. They carry a `failure_category`. For execution denials, such as insufficient credits, its value is `null`. Detected codes appear in the run's `errors` list with their explanations. Enable **Continue on Failure** to let the next block inspect the output. The Search failure category applies to the run only when the block ends it.

A terminated Search block shows its failure reason in the timeline instead of the result count.

```yaml
block_type: web_search
label: web_search_1
query: "site:example.com annual report"
provider: auto
num_results: 10
prompt: null
json_schema: null
error_code_mapping: null
```

Skyvern Cloud supplies provider credentials. Self-hosted installations configure `SERPAPI_API_KEY` and `EXA_API_KEY` in the server environment. Google pagination can use multiple API searches for a single block run.

### File Parser

Parse PDFs, CSVs, Excel files, images, DOCX files, and ZIP archives.

ZIP inputs are unzipped, and the block outputs the extracted file list as `file_name`, `file_path`, and `file_size`. Data Schema is ignored for ZIP inputs; loop over the file list and pass each `file_path` to another File Parser block to parse individual files.

Very large files can exceed the parser's time budget and fail the block. When a File Parser sits inside a loop, set **On block failure** (Advanced Settings) to *Skip to next iteration* so files that cannot be parsed are skipped and the rest of the list still runs.

| Field | Type | Description |
|-------|------|-------------|
| **File URL** | text | URL or parameter reference to the file |
| **Data Schema** | JSON | Schema for the extracted output. Enable the checkbox to reveal the editor. |
| **Model** | selector | Which LLM model to use |

### Google Sheets Read

Read cells from a Google Sheet. Connect a Google account with Google Sheets access on [Integrations](/cloud/integrations#google-and-microsoft-accounts) first.

| Field | Type | Description |
|-------|------|-------------|
| **Google Account** | selector | The connected account used to open the spreadsheet |
| **Spreadsheet** | selector | Search your spreadsheets or paste a spreadsheet URL |
| **Sheet Name** | text | The tab to read, e.g. `Sheet1` |
| **Range** | text | Optional. An A1 range such as `A1:D10`, or a named range. Leave it empty to read all rows. |
| **Has Header Row** | switch | Use the first row as column names (default: on) |

The output holds `values`, a list of rows with one list of cell values each. With **Has Header Row** on, `rows` holds one object per remaining row, keyed by the header; with it off, `rows` is `null`. The output also includes `spreadsheet_id`, `range`, `sheet_title`, `cells` and `merges`.

### Google Sheets Write

Write rows to a Google Sheet, through the same Google Sheets connection as Google Sheets Read.

| Field | Type | Description |
|-------|------|-------------|
| **Google Account** | selector | The connected account used to open the spreadsheet |
| **Spreadsheet** | selector | Search your spreadsheets or paste a spreadsheet URL |
| **Write Mode** | select | `Append rows` (default) adds rows below the existing data. `Update range` overwrites the cells in **Range**. |
| **Sheet Name** | text | The tab to write to |
| **Range** | text | With `Update range`, the cells to overwrite in A1 notation (e.g. `A2:D5`) or a named range; the data must match its shape. With `Append rows`, an optional start column such as `D:D`. |
| **Values** | text | A JSON array, or a reference that resolves to one, such as an earlier block's output. A list of lists writes each inner list left to right as one row. |
| **Column Mapping** | mapping | Required when **Values** holds objects. Maps each field to a column letter (`A`, `B`) or to a header name. |

Turn on **Create sheet if missing** in **Advanced Settings** to create the tab before writing. You need it when the sheet name changes per iteration, such as `sheet_{{ current_index }}`.

The output includes `rows_written`, `updated_range`, `write_mode` and `spreadsheet_id`.

### Power BI Query

Run a read-only DAX query against a Power BI dataset. Power BI is available on Enterprise plans.

| Field | Type | Description |
|-------|------|-------------|
| **Power BI account** | selector | A connected Power BI account with access to read the dataset |
| **Dataset / semantic model** | selector | The dataset to query. Click **Use a workflow parameter** to pass its ID as an input instead. |
| **DAX query** | text | A read-only query, e.g. `EVALUATE 'Table'` |
| **Maximum rows** | number | From 1 to 100,000 (default: 1000). A result with more rows than this fails the query instead of returning part of it. |

The DAX query must be literal text. The dataset can be literal text or a single input parameter reference, such as `{{ dataset_id }}`. The block runs only when the person who connected the Power BI account starts the run from the agent editor; other runs fail. The output is a list of row objects.

## Control Flow

### Loop

Repeat a sequence of blocks. Child blocks are placed inside the loop on the canvas. The block has two tabs: **For each** runs the blocks once per item in a list, and **While** runs them as long as a condition stays true.

**For each** fields:

| Field | Type | Description |
|-------|------|-------------|
| **Loop Value** | text | The list to iterate over. Use a parameter reference (e.g., `{{ my_list }}`) or a natural language description (e.g., "Extract links of the top 5 posts"), which adds an extraction step that builds the list. |
| **Data Schema** | JSON | Shape of the extracted items. Applies only when **Loop Value** is a natural language description. |
| **Continue if Empty** | boolean | Complete the loop successfully and continue the agent if the list is empty |
| **Continue Workflow if Loop Fails** | boolean | Let the rest of the agent run when the loop ends in failure |
| **Skip Iterations that Fail** | boolean | When an iteration fails, skip its remaining blocks and start the next iteration |

**While** fields:

| Field | Type | Description |
|-------|------|-------------|
| **Loop Condition** | expression | Jinja expression or natural language, checked before each iteration. Defaults to `{{ true }}`. |
| **Continue Workflow if Loop Fails** | boolean | Let the rest of the agent run when the loop ends in failure |
| **Skip Iterations that Fail** | boolean | When an iteration fails, skip its remaining blocks and start the next iteration |

If the condition is false at the first check, the child blocks never run and the loop succeeds with an empty output. Either kind of loop stops at 1000 iterations and fails with `Reached max_loop_iterations limit of 1000`.

Inside loop blocks, use these [reserved variables](/cloud/studio#values-every-agent-has):
- `{{ current_value }}`: the current item. `{{ current_item }}` holds the same value.
- `{{ current_index }}`: the iteration number (0-based)

A **While** loop sets only `{{ current_index }}`.

<Frame>
<img width="400" src="/images/cloud/block-loop-config.png" alt="Loop block configuration" />
</Frame>

Use **For each** when the item list is already known before the loop starts, such as rows extracted from a table, files uploaded by a user, or URLs passed as agent parameters.

Use **While** when the number of iterations is discovered during the run, such as pagination, polling, or retrying until a recoverable page state clears. For pagination, a common pattern is to extract a `has_next_page` boolean inside the loop, click Next, and let the next condition check decide whether to continue.

**Example Jinja2 expression:**

### Code

Execute custom Python code. Input parameters are available as global variables. Top-level variables in your code become the block's output.

| Field | Type | Description |
|-------|------|-------------|
| **Code** | code editor | Python code to execute |
| **Input Parameters** | select | Parameters available as globals in the code |

Code can import `asyncio`, `datetime`, `html`, `json` and `re`. Each one binds the
sandbox's own version of the module, which carries part of the standard library and
loads nothing. The same names are already available without an import.

| Module | What it provides |
|---|---|
| `asyncio` | `sleep` |
| `datetime` | `datetime`, `date`, `timedelta`, `timezone`, `UTC` |
| `html` | `escape` |
| `json` | `dumps`, `loads` |
| `re` | `match`, `search`, `findall`, `finditer`, `fullmatch`, `sub`, `compile`, `split`, `escape`, and the `I`, `S`, `IGNORECASE`, `MULTILINE` and `DOTALL` flags |

Every other module is refused, as is `import *` from an allowed module and a name
that starts with an underscore. Saving an agent whose new or changed code holds a
refused import returns `422` and names the block; code that is already saved stays
saveable. A name an import binds is left out of the block's output.

Password credential input parameters expose plaintext fields such as
`login_credential.username` and `login_credential.password`. These values are
readable by Python code inside the runner; they are not opaque handles. Use them
only where needed, such as passing them directly to browser operations.

For one-time codes, use `await login_credential.otp()`, the supported pattern
across both execution paths. Do not rely on `.totp` or the top-level `otp(...)`
helper, whose behavior differs between paths. If no OTP source is configured,
`login_credential.otp()` fails with a clear one-time-code-unavailable error.

```python
await page.fill("#username", login_credential.username)
await page.fill("#password", login_credential.password)
await page.fill("#otp", await login_credential.otp())
```

The sandbox does not reject code that prints, returns, or transforms credential
values. Before string values in a successful block output or a surfaced failure
reason are persisted, Skyvern masks exact registered-secret matches; registered
secrets of at least five characters are also masked inside larger strings. Derived
or transformed values may no longer match. Do not expose credentials through output
or errors.

### Agent

The Agent block lets a model choose which tools to call until it can return the fields in its Data Schema.

<Note>
The Agent block is available to selected organizations. Contact support to enable it.
</Note>

| Field | Type | Description |
|-------|------|-------------|
| **Prompt** | text | What the model should find out or do. Use `{{ input_name }}` to reference an input value |
| **Data Schema** | JSON | The answer the block returns, as a JSON object schema. Defaults to one required string field, `answer`. Later blocks read the answer as `{{ <label>_output.output }}`, and a Conditional can branch on it |
| **Inputs** | select | Inputs and earlier block outputs this block uses. Login can sign in only with a credential listed here. The model can read every input and earlier output in the run either way, with secret values masked |
| **Max Turns** | number | Turns the model may take, from 1 to 200. Defaults to 25. When the turns run out, the model gets one more turn in which it can only return its answer; the block fails if that turn does not produce a valid answer |
| **Tools** | multi-select | The tools the model may call |

The model can always read this run's data (`read_run_data`) and return its answer (`finish`). Without a Tools list it has no other tools. A new Agent block starts with these checked: **Browser Task**, **Download**, **File Download**, **Web Search**, **Go to URL**, **Click**, **Input Text** and **Extract Data**. The Tools checklist in the editor lists every optional tool, and checking one offers it to the model, except Login, which also needs a credential in Inputs.

A tool named after a block, such as **Browser Task** or **HTTP Request**, runs that block as an ordinary block and is billed as usual. **Go to URL**, **Click**, **Input Text** and **Extract Data** act on the run's current page. **Browser Task**, **File Download** and **Login** each start a separate browser agent that uses your organization's default step limit.

To sign in, check **Login** in Tools and add a credential to Inputs. Login is not checked by default. Skyvern masks the run's registered secrets in the tool results the model reads and in the recorded tool calls. The answer is saved as the model returns it, so do not ask the model to return a secret.

[Copilot](/cloud/studio#build-with-copilot) can add an Agent block to your agent and choose its Tools.

### Agent Trigger

Start another agent from this one.

| Field | Type | Description |
|-------|------|-------------|
| **Target Agent** | selector | The agent to start. The current agent is not listed. |
| **Payload** | fields | One field per input of the target agent. Values support [parameter references](/cloud/studio#inputs). |
| **Browser Session** | select | `Continue in the same session` (default) shares tabs, cookies and login state with the triggered agent. `Create a new browser` gives it a fresh browser. Click **Use dynamic value** to enter a browser session ID instead, such as `{{ browser_session_id }}`. |
| **Wait for Completion** | switch | Wait for the triggered agent to finish before the next block runs (default: on) |

With **Wait for Completion** on, the block succeeds only when the triggered run completes. Its output holds `workflow_run_id`, `workflow_permanent_id`, `status`, `failure_reason` and `outputs`, which holds the triggered agent's block outputs by name.

With it off, the triggered agent starts in the background and the next block runs at once. The output holds `workflow_run_id`, `workflow_permanent_id` and `status: "queued"`. `Continue in the same session` is unavailable, because this agent may close its browser before the triggered one finishes.

Agents can trigger each other at most 10 levels deep.

### Terminate

End the run as `terminated` with a reason you write. Put one on a Conditional branch to stop a run before the part that spends steps. See [pre-flight check](/developers/production#pre-flight-check).

| Field | Type | Description |
|-------|------|-------------|
| **Reason** | text | Required. Why the run stops here. Becomes the run's `failure_reason`. Supports [parameter references](/cloud/studio#inputs), for example `No account matches {{ account_number }}`. |
| **Error Code (Optional)** | text | A code added to the run's `errors`, so a retry rule, the run list filter, or a webhook can tell this stop apart. At most 128 characters of ASCII letters, digits, underscores, periods, colons, and hyphens. Supports parameter references. |

Neither field can reference a credential or a secret. A template that references one is dropped, and the run still stops with a reason that names the block. **Continue on Failure** does not apply: the run always ends here.

```yaml
block_type: terminate
label: skip_target
reason: "Pre-flight reported {{ target_url }} is not reachable"
error_code: PRECHECK_UNREACHABLE
```

### PDF Fill

Fill in a PDF form from a prompt and a JSON payload, and save the filled PDF as a file of the run.

| Field | Type | Description |
|-------|------|-------------|
| **File URL** | text | The source PDF: a URL, an S3 URI, or a file path from an earlier block's output |
| **Prompt** | text | How to fill the PDF fields. Supports [parameter references](/cloud/studio#inputs). |
| **Payload** | JSON | The data to fill in (default: `{}`). Supports [parameter references](/cloud/studio#inputs). |
| **Model** | selector | Which LLM model maps the payload to the fields |

The block works best on fillable PDFs with form fields. A scanned or flat PDF is filled best-effort by placing text on the page, and fails if it has more than 25 pages. `fill_mode` in the output is `acroform` for a fillable form and `flat_overlay` for a flat one.

The output also includes `fields`, `skipped_fields`, `file_path`, `file_name`, `artifact_url` and `downloaded_files`.

### Split PDF

Split one PDF into several PDFs, following a prompt that says where each document starts and ends.

| Field | Type | Description |
|-------|------|-------------|
| **File URL** | text | The source PDF: a URL, an S3 URI, or a file path from an earlier block's output |
| **Prompt** | text | How to split the PDF, e.g. "Split the PDF into one file per document." Supports [parameter references](/cloud/studio#inputs). |
| **Model** | selector | Which LLM model plans the split |

The block reads at most 1000 pages. A longer PDF fails with a message to split the source PDF into smaller files first.

The output holds `documents`, one entry per new PDF with its `name`, `folder`, `page_range`, `page_count`, `file_path`, `file_name` and `artifact_url`. It also includes `document_count`, `skipped`, `source_page_count` and `downloaded_files`.

### Email Inbox

Read messages from a connected Gmail or Outlook account and keep the ones a prompt describes. Connect the account on [Integrations](/cloud/integrations) first.

| Field | Type | Description |
|-------|------|-------------|
| **Email Client** | select | `Gmail` or `Outlook` |
| **Google Account** / **Microsoft Account** | selector | The connected account to read from. The label follows the Email Client. |
| **Folder** | text | Gmail label or Outlook folder to read. Defaults to the inbox. |
| **Match prompt** | text | Describes which emails to keep. Leave it blank to keep every email the filters return. |

Fields under **Optional Filters:**

| Field | Type | Description |
|-------|------|-------------|
| **Sender** | text | Only include emails from this sender |
| **Subject** | text | Only include emails matching this subject |
| **Newer Than Days** | number | Only include emails newer than this many days |
| **Max Results** | number | Maximum number of emails to return (default: 25, max: 100) |
| **Include Body** | switch | Include email body text in the results (default: on). When off, **Match prompt** cannot see message bodies either. |
| **Download Attachments** | switch | Download attachments from matched emails (default: off) |

Folder, Match prompt, Sender and Subject support [parameter references](/cloud/studio#inputs).

The output holds `email_client`, `folder`, `candidate_count`, `matched_count` and `emails`.

Turn on **Download Attachments** to pass files from matched emails to later blocks. Skyvern saves each matched email's attachments as run downloads and adds `downloaded_files` and `downloaded_file_urls` to the output. A saved attachment also carries its `file_name`, `file_path` and `url` in `emails`. Inline images are skipped. Attachments count toward the same per-file size, per-run size and file-count limits as browser downloads; an attachment that exceeds a limit or cannot be saved carries a `download_error` instead of failing the block.
